# Стенд: приложение, которое мы тестируем

Тесты не работают в пустоте — им нужно приложение. Это **EspoCRM**: система управления клиентами с веб-интерфейсом, REST API и базой MySQL. Она живёт в контейнерах Docker прямо на твоём компьютере.

---

## Запуск и остановка

Правой кнопкой по `stand/start-stand.ps1` → «Выполнить с помощью PowerShell».

Через 5–10 секунд увидишь:

```
Стенд готов: http://localhost:8080
Логин: admin
Пароль: в файле .env рядом с этим скриптом
```

Окно можно закрывать — стенд продолжит работать.

Остановка — `stand/stop-stand.ps1`. Она освобождает около 1.8 ГБ памяти.

**Перед выключением компьютера останавливать стенд не обязательно.** При выключении всё гаснет само, а база восстанавливается по журналу транзакций — это проверено. Скрипт остановки нужен в другом случае: ты закончил тренировки, но продолжаешь работать за компьютером и хочешь вернуть память.

После перезагрузки стенд **сам не поднимется** — это сделано намеренно, чтобы он не занимал память в фоне. Запускай `start-stand.ps1`.

## Как это устроено

Три контейнера Docker:

| Контейнер | Что делает |
|---|---|
| `espocrm` | веб-приложение, порт 8080 |
| `espocrm-mysql` | база данных, порт 3306 |
| `espocrm-daemon` | фоновые задачи приложения |

Docker установлен **внутрь WSL2** — подсистемы Linux в Windows, а не через Docker Desktop. Так не нужны права администратора и нет вопросов с лицензией Docker Desktop на рабочей машине.

### Почему у запуска есть «якорь»

В `start-stand.ps1` есть кусок, запускающий фоновый процесс `sleep`. Это не костыль ради костыля, а решение конкретной проблемы: **WSL гасит виртуальную машину, как только закрывается последняя сессия**. Без якоря стенд умирал сразу после закрытия окна скрипта, и браузер показывал пустую страницу.

Якорь снимается автоматически при `stop-stand.ps1`.

## Тестовые данные

В базе лежит готовый набор в домене «металлообработка»:

| Сущность | Записей |
|---|---|
| Компании (Accounts) | 15 |
| Контактные лица (Contacts) | 30 |
| Сделки (Opportunities) | 24 |
| Лиды (Leads) | 18 |
| Задачи (Tasks) | 14 |

Данные разнообразны по справочникам: сделки распределены по всем шести стадиям, компании — по четырём отраслям. Это важно: на однообразных данных нельзя проверить ни фильтры, ни сортировку.

### Если тесты намусорили

```powershell
.\restore-db.ps1
```

Восстанавливает базу из эталонного дампа за несколько секунд. Пользуйся этим смело — именно для этого дамп и лежит в репозитории.

Пересоздать данные через API (медленнее, зато видно, как они собираются):

```powershell
.\seed-data.ps1 -Clean
```

Сохранить свой снимок перед экспериментом:

```powershell
.\backup-db.ps1 -Name before-experiment
```

## Подключение к базе

Для DBeaver или любого другого клиента:

| Параметр | Значение |
|---|---|
| Host | `localhost` |
| Port | `3306` |
| Database | `espocrm` |
| Username | `espocrm` |
| Password | `MYSQL_PASSWORD` из `stand/.env` |

**Обязательно** на вкладке *Driver properties* выставь `allowPublicKeyRetrieval = true` и `useSSL = false`. Без этого MySQL 8 не пустит: он использует аутентификацию `caching_sha2_password`, и по незашифрованному соединению клиенту нужно явно разрешить запросить публичный ключ сервера. Это первое, обо что спотыкаются все.

Две особенности схемы, без знания которых запросы врут:

1. **Удаление мягкое.** EspoCRM не стирает строки, а ставит `deleted = 1`. Любой запрос без `WHERE deleted = 0` покажет больше записей, чем интерфейс.
2. **`lead` — зарезервированное слово MySQL.** В запросах нужны обратные кавычки: ``SELECT * FROM `lead` ``.

## Если что-то не работает

Состояние контейнеров:

```powershell
wsl -u root -- bash ./stand.sh status
```

Лог приложения — здесь видны причины отказов API: валидация, дубли, кодировка:

```powershell
wsl -u root -- bash ./stand.sh applog
```

Лог контейнера — здесь видно, почему контейнер не поднялся:

```powershell
wsl -u root -- bash ./stand.sh logs
```

Разница между последними двумя важна на практике: `logs` отвечает на вопрос «почему контейнер не стартовал», `applog` — «почему запрос вернул 400 или 500». Привыкай смотреть лог приложения: коды ответов почти ничего не объясняют, а лог называет точную причину.

### VPN

При поднятом VPN у WSL нет доступа в интернет: VPN перехватывает маршруты на стороне Windows, а NAT-сеть WSL туда не попадает. Стенду это не мешает — образы уже скачаны. Но если понадобится скачать что-то новое, отключи VPN на время.
