# Развёртывание с нуля на новой машине

Инструкция на случай, если этот компьютер придётся сменить, переустановить систему или ты захочешь поднять проект дома.

Проверено на Windows 11. Права администратора **не нужны** ни на одном шаге.

---

## Что понадобится

| Нужно | Зачем | Проверка, что уже есть |
|---|---|---|
| WSL2 с Ubuntu | в нём живёт Docker | `wsl -l -v` |
| Docker Engine внутри WSL | контейнеры стенда | `wsl -u root -- docker version` |
| JDK 21 | компиляция и запуск тестов | `java -version` |
| Git | работа с репозиторием | `git --version` |
| IntelliJ IDEA | среда разработки | — |

## Шаг 1. WSL2

Проверь, что есть и какой версии:

```powershell
wsl -l -v
```

Если дистрибутива нет:

```powershell
wsl --install -d Ubuntu
```

Если дистрибутив есть, но в колонке VERSION стоит **1** — это критично: **на WSL1 Docker не работает в принципе.** Там нет настоящего Linux-ядра, нет cgroups и нет таблицы `nat` в iptables. Переводи на вторую версию:

```powershell
wsl --set-version Ubuntu 2
```

Займёт несколько минут, данные внутри сохранятся.

> На этом этапе в прошлый раз и застряли: `wsl --status` показывал «версия по умолчанию: 2», но это относится только к **новым** дистрибутивам, а установленный остался на первой версии.

## Шаг 2. Ограничить аппетиты WSL

Создай файл `C:\Users\<имя>\.wslconfig`:

```ini
[wsl2]
memory=8GB
swap=2GB

networkingMode=NAT
localhostForwarding=true

[experimental]
autoMemoryReclaim=gradual
```

Что здесь важно:

**`memory`** — потолок, а не резерв. Виртуалка берёт сколько нужно и отдаёт всё при `wsl --shutdown`. Без этой строки по умолчанию может занять до 8 ГБ.

**`networkingMode=NAT`** — обязательно для нашей задачи. В этом режиме порты, которые слушает WSL, видны в Windows как `localhost`. Именно так Selenide с Windows достукивается до `http://localhost:8080`.

Есть соблазн поставить `mirrored` — в нём WSL видит сеть Windows и работает интернет через VPN. Но тогда WSL прикрывается Hyper-V firewall с политикой `DefaultInboundAction = Block`, и входящие соединения Windows → WSL режутся: тесты до стенда не достучатся. Отключать firewall ради удобства не стоит.

Плата за `NAT`: **при поднятом VPN у WSL нет интернета**. Для работы стенда это не мешает (образы уже скачаны), но для их первой загрузки VPN придётся отключить.

Применить файл:

```powershell
wsl --shutdown
```

## Шаг 3. Docker внутрь WSL

Без прав администратора Windows и без Docker Desktop.

```powershell
wsl -u root
```

Дальше внутри Ubuntu:

```bash
apt-get update
apt-get install -y ca-certificates curl gnupg
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

### Обязательно: переключить iptables

Ядро WSL не поддерживает nftables, а `iptables` версии 1.8 по умолчанию работает через них. Без этого шага демон Docker не стартует с ошибкой `Failed to initialize nft: Protocol not supported`:

```bash
update-alternatives --set iptables /usr/sbin/iptables-legacy
update-alternatives --set ip6tables /usr/sbin/ip6tables-legacy
```

### Автозапуск Docker

```bash
cat > /etc/wsl.conf <<'EOF'
[boot]
command = service docker start
EOF
```

Проверка:

```bash
service docker start
docker run --rm hello-world
```

Должно вывести `Hello from Docker!`.

## Шаг 6. Пароли

В репозитории паролей нет — только шаблоны. Создай два файла из них.

**`stand\.env`** — скопируй из `stand\.env.example` и задай свои пароли:

```ini
ESPOCRM_PORT=8080
ESPOCRM_ADMIN_USERNAME=admin
ESPOCRM_ADMIN_PASSWORD=<придумай пароль>
MYSQL_PASSWORD=<придумай пароль>
MYSQL_ROOT_PASSWORD=<придумай пароль>
MYSQL_PORT=3306
```

**`src\test\resources\env\local.properties`** — скопируй из `local.properties.example`. Пароли должны **совпадать** с теми, что в `stand\.env`:

```ini
url=http://localhost:8080
adminLogin=admin
adminPass=<тот же, что ESPOCRM_ADMIN_PASSWORD>

dbUrl=jdbc:mysql://localhost:3306/espocrm?allowPublicKeyRetrieval=true&useSSL=false&serverTimezone=UTC&characterEncoding=UTF-8
dbUser=espocrm
dbPass=<тот же, что MYSQL_PASSWORD>
```

## Шаг 7. Запуск стенда

```powershell
cd stand
.\start-stand.ps1
```

Первый запуск дольше: Docker скачивает образы EspoCRM и MySQL, около 1.5 ГБ. **Если поднят VPN — отключи его на это время**, иначе скачивание не пойдёт.

Дождись `Стенд готов: http://localhost:8080` и проверь в браузере.

## Что может пойти не так

| Симптом | Причина и лечение |
|---|---|
| `docker: command not found` | не выполнен шаг 3, либо не в WSL, а в PowerShell |
| `Failed to initialize nft: Protocol not supported` | не переключён iptables на legacy |
| `Cannot connect to the Docker daemon` | демон не запущен: `service docker start` |
| Образы не скачиваются | поднят VPN — отключи на время |
| Стенд поднялся, но тесты не достучались | в `.wslconfig` стоит `mirrored` вместо `NAT` |
| `Public Key Retrieval is not allowed` | в строке JDBC потерялся `allowPublicKeyRetrieval=true` |
| Тесты падают сразу все | стенд не поднят |
| Стенд умирает сразу после закрытия окна | не сработал «якорь» из `start-stand.ps1` |

## Если понадобится перенести данные

Стенд целиком переносится дампом. На старой машине:

```powershell
cd stand
.\backup-db.ps1 -Name перенос
```

Скопируй `stand\backup\espocrm-перенос.sql.gz` на новую машину в ту же папку и там:

```powershell
.\restore-db.ps1 -Name перенос
```
