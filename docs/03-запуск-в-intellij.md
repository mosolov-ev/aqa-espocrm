# Запуск в IntelliJ IDEA

---

## Открыть проект

1. Запусти IntelliJ IDEA (ярлык на рабочем столе).
2. **File → Open**.
3. Выбери папку `C:\Users\Evgeny\IdeaProjects\aqa-espocrm` — именно папку, не файл внутри неё.
4. **Open**. Если спросит «Open as Project» — соглашайся.
5. Если спросит «Trust Project?» — **Trust Project**.

Внизу справа пойдёт индикатор загрузки: IDEA читает `build.gradle` и скачивает зависимости. Первый раз это занимает пару минут, дальше — секунды.

Готовность видно по дереву проекта слева: папка `src/test/java` должна подсветиться, а классы перестать быть красными.

### Если классы красные и не находятся

Правой кнопкой по `build.gradle` → **Link Gradle Project**. Либо открой панель Gradle (значок слоника справа) и нажми **Reload All Gradle Projects** — круговые стрелки.

---

## Перед запуском тестов

**Стенд должен быть поднят.** Без него упадут все тесты, кроме проверки окружения.

Запусти `stand\start-stand.ps1` и убедись, что http://localhost:8080 открывается.

Это самая частая причина «вдруг всё сломалось»: стенд не запущен после перезагрузки компьютера.

## Запуск через готовые конфигурации

В верхней панели, слева от зелёного треугольника, есть выпадающий список. В нём семь готовых конфигураций:

| Конфигурация | Что запускает | Сколько идёт |
|---|---|---|
| `1 Все тесты` | весь набор | ~30 секунд |
| `2 Только UI` | тесты интерфейса | ~20 секунд |
| `3 Только API` | тесты REST API | ~5 секунд |
| `4 Только БД` | сверку с базой | ~5 секунд |
| `5 Smoke` | самые важные из каждой группы | ~10 секунд |
| `6 UI без окна браузера` | UI в headless-режиме | быстрее обычного |
| `7 Отчёт Allure` | собирает и открывает отчёт | — |

Выбери нужную и нажми зелёный треугольник (или **Shift+F10**).

Эти конфигурации лежат в папке `.run` и хранятся в репозитории — поэтому они появятся сами на любой машине, где ты склонируешь проект. В отличие от папки `.idea`, которая в git не попадает: там личные настройки среды, а не переносимые настройки запуска.

## Запуск отдельного теста

Три способа, от самого удобного:

**По зелёному треугольнику в поле редактора.** Открой класс теста — слева от имени класса и каждого метода есть треугольник. Клик по нему → **Run**.

**Правой кнопкой по файлу** в дереве проекта → **Run '...'**.

**Из терминала IDEA** (внизу, вкладка Terminal):

```bash
.\gradlew.bat test --tests "ru.espocrm.tests.ui.LoginTest"
```

Терминал IDEA открывается сразу в папке проекта, поэтому `cd` не нужен.

> **Про ошибку «Имя .\gradlew.bat не распознано».** Запись `.\` означает «файл в текущей папке». Если ты в `C:\Windows\System32` или в домашней папке, файла там нет. Перейди в папку проекта:
> ```bash
> cd C:\Users\Evgeny\IdeaProjects\aqa-espocrm
> ```
> Проверить, что ты на месте: `dir gradlew.bat` — файл должен найтись.

## Как читать результат

После прогона внизу открывается панель **Run** с деревом тестов.

- **Зелёная галочка** — тест прошёл.
- **Красный крест** — упал. Кликни по нему: справа покажется, что ожидалось и что получилось.
- **Жёлтый** — пропущен.

У упавшего UI-теста в тексте ошибки будут две ссылки:

```
Screenshot: file:/C:/.../build/reports/tests/1795438888615.0.png
Page source: file:/C:/.../build/reports/tests/1795438888615.0.html
```

Это скриншот экрана в момент падения и полная разметка страницы. **Открывай их первым делом** — обычно сразу видно: не загрузилась страница, не тот элемент, появилось неожиданное окно.

### Типичные сообщения и что они значат

| Сообщение | Что произошло |
|---|---|
| `Element not found {...}` | локатор не нашёл элемент за отведённое время |
| `Element should be visible ... Actual value: hidden` | элемент есть в разметке, но скрыт. Часто нужно проверять `exist`, а не `visible` |
| `expected: X but was: Y` | проверка не сошлась, обе величины показаны |
| `Connection refused` | стенд не поднят |

## Отчёт Allure

Выбери конфигурацию `7 Отчёт Allure` и нажми Run. Отчёт соберётся и откроется в браузере.

**Важно:** `allureServe` поднимает локальный веб-сервер и **не завершается сам** — вкладка Run остаётся занятой, пока не остановишь её красным квадратом. Это не зависание.

Если нужен отчёт файлом, без сервера:

```bash
.\gradlew.bat allureReport
```

Готовый отчёт: `build\reports\allure-report\allureReport\index.html` — открывается двойным кликом.

В отчёте интересны две вещи: дерево шагов из аннотаций `@Step` (видно сценарий целиком) и вложения у упавших тестов — скриншот и разметка.

## Запуск с параметрами

Все системные свойства доезжают до тестов — в `build.gradle` для этого есть строка `systemProperties System.properties`.

Без окна браузера:

```bash
.\gradlew.bat test "-Dselenide.headless=true"
```

Только группа тестов по тегу:

```bash
.\gradlew.bat test "-Dtag=api"
```

Другой адрес стенда:

```bash
.\gradlew.bat test "-Durl=http://localhost:9090"
```

> **Про кавычки.** В PowerShell аргумент с точкой нужно брать в кавычки, иначе он разбивается на части и Gradle ищет несуществующий таск. `-Dtag=api` без точки работает и без кавычек, а `-Dselenide.headless=true` — только в кавычках. Проще всегда ставить кавычки.

## Полезные сочетания клавиш

| Клавиши | Действие |
|---|---|
| **Shift+F10** | запустить последнюю конфигурацию |
| **Ctrl+Shift+F10** | запустить тест, на котором стоит курсор |

| **Ctrl+N** | найти класс по имени |
| **Ctrl+Shift+F** | поиск по всему проекту |
| **Alt+Enter** | предложения по исправлению под курсором |

## Отладка теста

Когда непонятно, почему тест падает, пошаговая отладка объясняет быстрее любых логов.

1. Кликни в поле слева от номера строки — появится красная точка (breakpoint).
2. Запусти тест **Shift+F9** вместо Shift+F10.
3. Выполнение остановится на этой строке. Внизу откроется панель Debug со значениями всех переменных.
4. **F8** — следующая строка, **F7** — зайти внутрь метода, **F9** — продолжить до следующей точки.

Отдельно полезно: пока тест стоит на точке останова, **браузер остаётся открытым**, и можно руками посмотреть, что на странице, открыть инструменты разработчика и проверить локатор.

Умение пользоваться отладчиком — то, что отличает инженера от человека, который вставляет `System.out.println` и перезапускает тест двадцать раз.
