# Локальный стенд EspoCRM

Приложение, против которого гоняются автотесты из этого репозитория: CRM с веб-интерфейсом, REST API и базой MySQL. Поднимается в Docker одной командой.

Все скрипты вычисляют свой путь сами, поэтому папку можно перемещать куда угодно — ничего править не нужно.

---

## Запуск

Правой кнопкой по `start-stand.ps1` → «Выполнить с помощью PowerShell». Либо из консоли, находясь в этой папке:

```powershell
.\start-stand.ps1
```

| | |
|---|---|
| Адрес | http://localhost:8080 |
| Логин | `admin` |
| Пароль | в файле `.env`, параметр `ESPOCRM_ADMIN_PASSWORD` |
| REST API | http://localhost:8080/api/v1/ |
| MySQL | `localhost:3306`, база `espocrm`, пользователь `espocrm` |

Остановка — `.\stop-stand.ps1`. Она гасит контейнеры и освобождает ~1.8 ГБ памяти. Перед выключением компьютера запускать её не обязательно: при выключении всё гаснет само, а база восстанавливается по журналу транзакций.

## Файлы

| Файл | Назначение |
|---|---|
| `docker-compose.yml` | описание контейнеров: EspoCRM, MySQL, фоновый демон |
| `.env` | пароли и порты. **В git не попадает** |
| `.env.example` | шаблон `.env` для новой машины |
| `start-stand.ps1` / `stop-stand.ps1` | запуск и остановка |
| `seed-data.ps1` | наполнение тестовыми данными через REST API |
| `backup-db.ps1` / `restore-db.ps1` | резервная копия и восстановление базы |
| `stand.sh`, `db.sh` | внутренняя логика, вызывается из скриптов выше |
| `backup/espocrm-seed.sql.gz` | эталонный дамп базы с тестовыми данными |

## Тестовые данные

В базе лежит готовый набор в домене «металлообработка»: 15 компаний, 30 контактных лиц, 24 сделки, 18 лидов, 14 задач. Данные разнообразны по справочникам — есть на чём отрабатывать фильтры, поиск и сортировку.

Быстро вернуть базу в исходное состояние, если тесты намусорили:

```powershell
.\restore-db.ps1
```

Создать данные заново через API (медленнее, но показывает, как они собираются):

```powershell
.\seed-data.ps1 -Clean
```

Снять свой снимок базы:

```powershell
.\backup-db.ps1 -Name before-experiment
```

## Развёртывание на новой машине

Полная инструкция — в `docs/06-развёртывание-с-нуля.md`. Кратко:

1. Включить WSL2 и поставить Ubuntu.
2. Установить Docker Engine внутрь WSL.
3. Скопировать `.env.example` в `.env` и задать свои пароли.
4. Запустить `start-stand.ps1`.
5. Восстановить данные: `restore-db.ps1`.

## Если что-то не работает

Состояние контейнеров:

```powershell
wsl -u root -- bash ./stand.sh status
```

Лог приложения — там видны причины отказов API (валидация, дубли, кодировка):

```powershell
wsl -u root -- bash ./stand.sh applog
```

Лог контейнера — там видно, почему контейнер не поднялся:

```powershell
wsl -u root -- bash ./stand.sh logs
```

Важная особенность: **стенд не поднимается сам после перезагрузки компьютера** — это сделано намеренно, чтобы он не занимал память в фоне. После включения компьютера запускай `start-stand.ps1`.

Вторая особенность: при поднятом VPN у WSL нет доступа в интернет (NAT-сеть не попадает в VPN-маршруты). Стенду это не мешает — образы уже скачаны. Но если понадобится скачать что-то новое, отключи VPN на время.
